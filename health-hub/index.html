Pattern 1 · Ownership

Separate what's mine from what the AI writes

"The number is the datum. The phrasing is the template."

Mine
The data
Sets, reps, loads, the schedule, a workout log that only ever appends. Bare numbers, no units, no prose. Lives on a disk I own.
The AI's
Everything else
The renderer, the templates, the checks, the editor. It can rewrite every page from scratch without touching one of my numbers.
The enforcement
A rule that stops the build
Put a unit inside a value and the build refuses. Type a total by hand instead of deriving it and a test fails.

Why it matters: the AI can be wrong, slow, or replaced. My data survives all three.

Pattern 2 · Specification

Write the rubric before the code

  • Every stage starts with a written rubric. MUST items are pass or fail. One MUST failure fails the whole stage, no matter how good the rest is. SHOULD items are scored but never block.
  • Non-scope is spelled out. "No backend, no editor, no database. A submission that starts building any of them fails." The AI's favorite move is to do more than asked.
  • The first refactor had one criterion: byte-identical output before and after. "It looked wrong so I fixed it" is a separate change and does not belong in this stage.
  • Refusal is allowed, in writing. A SHOULD can be declined with a reason. Silent omission cannot.
Pattern 3 · Review

Four hostile graders

Each round, the AI builds, then plays four adversarial reviewers against its own work. Each has a veto in its own lane. Their job is to find what's wrong, not confirm what's right.

Usability
Me at 6am, on a phone, mid-set, cold hands
Can I find today's protocol in one tap? Log a set without losing my place? Is anything important below three scrolls?
Style
A designer who has seen 10,000 dark dashboards
Does the density read as considered or dumped? Does anything look like a default?
Domain skeptic
A coach who thinks most of this is expensive urine
Is every claim traceable to the source sheet? Is a C-grade claim presented with the confidence of an A?
Domain expert
Someone who knows the literature's failure modes
Is animal data dressed as human data? Can a reader mistake an intention for a practice?
Minimum five rounds. It ran eleven. A grader that reports nothing is a failed grader, not a passed build Findings carry forward until closed by a fix or a refusal the grader accepts
Pattern 4 · Learning

The rubric is a deliverable too

Anything a grader found that the rubric did not anticipate got added to the rubric, not just fixed. Some of the rules it wrote about itself:

A test that asserts presence is not a safety test.
132 safety flags could be inverted without changing a byte of any page or failing any check. Tests now assert consequences.
Verification scope is part of the claim.
A tool printed CLEAN over a file it had never looked at. Every check now names what it read.
A sweep that cannot fail anything is not a check.
A full scan sat behind a flag nothing ever passed, and its result never fed the verdict.
"Did this resolve" needs a partner: "into what."
A placeholder resolved into garbage and shipped on every page for a full round, inside the fix meant to prevent it.
Every absence is named, or none is.
Four gaps were labeled "not recorded." The fifth and largest was silent, so readers assumed a blank meant something.
The deploy that is tested is the one that actually happens.
The test booted onto an empty disk, the one case that cannot fail. Real deploys boot onto yesterday's data.
Pattern 5 · Boundaries

Lines the AI can't talk its way past

Two sites, one source
Private and public are built separately
The private site has everything, behind Google sign-in. The public subset was never rendered with private data. Nothing was filtered out, because it was never put in.
The scanner
Publish refuses if anything leaks
Every brand, dose, and product name is a blocked term, with an adversarial test per term. If the scan objects, nothing moves.
Provenance
Every number must prove itself
A tool perturbs each value in the data and checks the page moved. A number on a page with no source in the data fails the build.

Honest round

What broke anyway

  • One failed deploy, site down. My data file also held program structure. New code needed a field the live file could not have. The test suite had no idea, because it only tested a fresh install.
  • One bug shipped inside its own fix. A CSS escape rendered as junk on every page for a full round, and the check that should have caught it only asked whether the placeholder resolved.
  • The pattern: every miss was a check that looked like a check and could not fail. The graders found what I did not know to look for. Nothing found what nobody was looking for.
  • The one thing still typed by hand: "82 minutes door to door." The build catches an impossible figure, not a merely wrong one.
The lens · Does it last?

What survives a cheaper model

Gets stronger
The structure
Data I own, a rubric in plain English, graders described as people, checks that must be able to fail. None of it cares which model runs it. Cheaper tokens mean more rounds, not fewer.
Stays human
The judgment
Deciding what is a MUST. Writing the non-scope. Being the 6am usability grader. Knowing which refusal to accept. The AI did not write the rubric's first draft well.
For the room: what's your equivalent of a hostile grader? Where do you let the AI mark its own homework? Is a rubric overkill for a one-person tool, or the only reason it worked?
